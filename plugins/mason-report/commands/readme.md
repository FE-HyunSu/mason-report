# 목표

새로 mason-report를 접하거나 리포트의 표기(예: "관찰 안 됨 (알수없음)")가 헷갈리는
사용자에게, 플러그인 사용법과 리포트 표기 기준을 그 자리에서 설명한다. 이 명령은 로그를
조회하거나 분석하지 않는다 — 순수하게 사용 안내 문서를 출력하는 정적 명령이다.

# 절차

아래 "출력 형식"은 한국어로 작성된 참고본(reference)이다. **사용자가 지금 이 대화에서
쓰고 있는 언어로** 같은 구조·같은 내용을 다시 작성해서 출력한다 — 이는 Claude가 평소
사용자 언어에 맞춰 응답하는 것과 동일한 기준이며, 사용자가 한국어로 대화 중이면 참고본을
그대로 사용해도 된다. 언어를 임의로 추측하기 위해 OS 로케일이나 국가 정보를 조회하지
않는다 — 이 대화에서 사용자가 실제로 쓰고 있는 언어를 그대로 따른다. 로그 조회나 계산이
필요 없으므로 Tool을 호출하지 않는다. 번역 시에도
`plugins/mason-report/skills/decision-analysis/SKILL.md`의 정의와 어긋나지 않게 유지한다 —
이 명령의 설명 내용이 그 Skill의 등급 기준을 요약한 것이기 때문이다.

# 출력 형식

아래 "출력 형식"은 **존댓말·짧은 단락**으로 쓴 참고본이다 — 문장을 길게 늘어뜨리지 않고,
한 단락에는 핵심 하나만 담는다. 세부 근거(예: 왜 "0%" 대신 "알수없음"을 쓰는지)는
`SKILL.md` 쪽이 이미 상세히 다루므로, 이 안내에서는 결론만 짧게 전달하고 필요하면
`SKILL.md`로 안내한다.

```markdown
# Mason Report 사용법

mason-report는 Claude Code가 요청을 어떻게 처리했는지, **실제로 관찰된 증거만**으로
재구성해서 보여드리는 로컬 도구입니다.

Claude의 비공개 생각 과정은 들여다보지 않습니다. 어디로도 전송하지 않고, 로컬에만
남습니다.

## 명령어

| 명령어 | 하는 일 |
|---|---|
| `/mason-report:latest [n]` | 최근 완료된 턴을 자동으로 골라 분석합니다 (기본 1턴) |
| `/mason-report:select [n]` | 원하는 턴을 직접 골라 분석합니다 |
| `/mason-report:all` | 현재 세션 전체를 턴 단위로 요약합니다 |
| `/mason-report:status` | 로그가 잘 쌓이고 있는지 확인합니다 |
| `/mason-report:readme` | 지금 보고 계신 이 사용법 안내입니다 |

## 리포트 구성

턴 하나를 분석하는 리포트(`/mason-report:latest`, `/mason-report:select`)는 항상 같은
세 부분으로 구성됩니다.

1. **입력된 프롬프트**: 지금 분석하는 프롬프트 원문을 가장 먼저 보여드립니다.
2. **로그**: 그 프롬프트로 인해 실제로 기록된 이벤트를, 성공/실패 판정조차 섞지 않고
   있는 그대로(raw) 표로 보여드립니다.
3. **분석**: "로그"에 있던 각 호출의 결과(성공/실패)부터, 어떤 문구가 어떤
   Skill/Rule/Tool을 발동시켰는지, 최종 답변이 로그와 맞는지까지 — 해석이 필요한
   모든 내용을 여기서 보여드립니다.

## 리포트에 붙는 태그

문장 끝에는 다음 세 태그 중 하나가 붙습니다.

- **observed (로그로 확인된 것)**: 실제로 일어난 일입니다.
- **inferred (정황상 추정된 것)**: 관찰된 행동으로 미루어 짐작한 설명입니다.
- **unknown (로그만으로 확인 불가)**: 로그만으로는 알 수 없는 부분입니다.

"2. 로그"의 태그는 항상 observed입니다(무엇이 기록됐는지 그 자체니까요). "3. 분석"
안에서도 "결과"는 observed지만, 트리거 매핑과 최종 답변 비교는 해석이 들어가므로
inferred/unknown이 섞입니다 — 등급이 낮다고 해서 "결과"까지 불확실한 건 아닙니다.
무엇을 했는지와 왜 했는지는 서로 다른 질문입니다.

## 3. 분석 — 트리거 매핑 표의 등급

"어떤 문구가 어떤 Skill/Rule/Tool을 발동시켰는가"를 나타내는 등급입니다.

| 등급 | 의미 |
|---|---|
| 확인됨 | 명시적 호출이 로그에 그대로 남아 있습니다 |
| 강한 추정 | 관련 파일 접근이 확인되고, 행동도 절차와 일치합니다 |
| 약한 추정 | 행동은 비슷하지만 파일 접근이나 명시적 호출은 없습니다 |
| 관찰 안 됨 | 관련 이벤트가 전혀 없습니다 |

한 가지만 기억해 주세요 — "관찰 안 됨"은 "관여하지 않았다"가 아니라 "판단할 근거 자체가
없다"는 뜻입니다. 그래서 숫자 대신 "알수없음"이라고만 적습니다.

## 트리거 매핑 표를 읽는 법

표는 `근거 문구 | 트리거 | 등급` 세 칸으로 구성됩니다.

- **근거 문구**: 판정의 근거가 된 프롬프트 원문(짧게 축약됨)입니다.
- **트리거**: `(Skill: dataviz)`, `(Rule: CLAUDE.md)`, `(Tool: Bash)`처럼 종류를 이름
  앞에 붙여 표시합니다.
- **등급**: 위 네 등급과 참고용 %입니다.

한 근거 문구가 여러 트리거에 걸치면, 한 셀에 몰아넣지 않고 행을 나눠 트리거 하나씩
적습니다.

## % 표기에 대해

표에 나오는 %(예: "약 70%")는 Claude 내부의 실제 확률이 아닙니다. 그런 값은 애초에
Hook에 존재하지 않습니다. 등급을 보기 쉽게 나타낸 참고용 수치일 뿐이니, 정확한 계산값으로
받아들이지 않으셔도 됩니다.

## 3. 분석 — 토큰 사용량

`/mason-report:latest`와 `/mason-report:select`는 **이미 끝난 턴**에 한해 실제 토큰
사용량도 "3. 분석 → 결과" 소절에 함께 보여드립니다. 추정이 아니라, API에 실제로 찍힌
수치를 그대로 더한 값입니다. Subagent를 사용했다면 그 토큰은 항상 따로 표시합니다.

아직 진행 중인 턴이나, 이 기능이 생기기 전에 기록된 옛 로그는 계산하지 않고 "확인
불가"로 남겨둡니다.

있습니다. 이 안내와 다르게 보이면 그쪽이 최신 기준입니다.
```
