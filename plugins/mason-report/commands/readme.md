# 목표

새로 mason-report를 접하거나 리포트의 표기(예: "관찰 안 됨 (알수없음)")가 헷갈리는
사용자에게, 플러그인 사용법과 리포트 표기 기준을 그 자리에서 설명한다. 이 명령은 로그를
조회하거나 분석하지 않는다 — 순수하게 사용 안내 문서를 출력하는 정적 명령이다.

# 절차

아래 "출력 형식"은 한국어로 작성된 참고본(reference)이다. **사용자가 지금 이 대화에서
쓰고 있는 언어로** 같은 구조·같은 내용을 다시 작성해서 출력한다 — 이는 Claude가 평소
사용자 언어에 맞춰 응답하는 것과 동일한 기준이며, 사용자가 한국어로 대화 중이면 참고본을
그대로 사용해도 된다. 언어를 임의로 추측하기 위해 OS 로케일이나 국가 정보를 조회하지
않는다 — 이 대화에서 사용자가 실제로 쓰고 있는 언어를 그대로 따른다. 로그 조회나 계산이
필요 없으므로 Tool을 호출하지 않는다. 번역 시에도
`plugins/mason-report/skills/decision-analysis/SKILL.md`의 정의와 어긋나지 않게 유지한다 —
이 명령의 설명 내용이 그 Skill의 등급 기준을 요약한 것이기 때문이다.

# 출력 형식

```markdown
# Mason Report 사용법

mason-report는 Claude Code가 요청을 어떻게 처리했는지, **공식 Hook 이벤트로 관찰 가능한
증거만**을 근거로 재구성해서 보여주는 로컬 관찰 도구다. Claude의 비공개
chain-of-thought는 조회하지 않는다 — 네트워크 호출도 없다.

## 명령어

| 명령어 | 무엇을 보여주나 |
|---|---|
| `/mason-report:latest [n]` | 가장 최근 완료된 사용자 턴(들)을 자동으로 골라 분석. 기본값 1턴 |
| `/mason-report:select [n]` | 최근 프롬프트 목록 중 하나를 직접 골라 그 턴만 분석 |
| `/mason-report:all` | 현재 세션 전체를 턴 단위로 요약 |
| `/mason-report:status` | 로그 수집이 실제로 되고 있는지, 어디에 저장되는지 진단 |
| `/mason-report:readme` | 지금 보고 있는 이 사용법/표기 안내 |

## 리포트에 붙는 태그: observed / inferred / unknown

리포트의 각 문장에는 다음 세 태그 중 하나가 붙는다.

- **observed**: Hook 이벤트나 transcript에서 직접 확인된 사실. "무슨 일이 있었는가"
- **inferred**: 관찰된 행동을 근거로 재구성한 설명. "왜 그랬을 것으로 보이는가"
- **unknown**: 지금 남아있는 로그만으로는 확인할 수 없는 부분

**"실행 흐름"** 블록의 태그는 대부분 observed다 — 뭘 했는지는 로그에 직접 남기 때문이다.
**"트리거 매핑"** 표의 등급이 낮다고 해서 실행 흐름 자체가 불확실하다는 뜻은 아니다.
실행 여부(observed)와 그 원인이 무엇이었는지(트리거 매핑)는 서로 다른 질문이다.

## 트리거 매핑 표의 등급: 확인됨 / 강한 추정 / 약한 추정 / 관찰 안 됨

"이 프롬프트의 어떤 문구가 어떤 Skill/Rule/Tool을 유발했는가"에 대한 등급이다.

| 등급 | 의미 | 참고용 수치 |
|---|---|---|
| 확인됨 | 명시적 호출이 로그에 직접 기록됨 (예: `/plugin:skill` 문자열, MCP tool_name 일치) | 90–100% |
| 강한 추정 | 해당 Skill 파일 접근이 확인되고, 이후 행동이 그 절차와 일치 | 60–89% |
| 약한 추정 | 행동은 절차와 비슷하지만 파일 접근·명시적 호출은 관찰 안 됨 | 20–59% |
| 관찰 안 됨 | 관련 이벤트가 전혀 관찰되지 않음 | 알수없음 (수치로 표기하지 않음) |

**중요 — 자주 오해하는 지점:** `관찰 안 됨 (알수없음)`는 "이 Skill/Rule/Tool이 관여하지
**않았다**"고 확인된 결과가 아니다. mason-report가 수집하는 Hook 이벤트에는 "Skill이
호출됐다"를 직접 알려주는 전용 이벤트가 없기 때문에, **관여했는지 여부 자체를 판단할
증거가 로그에 없는 상태**를 뜻한다. 그래서 이 등급에는 "0%" 같은 숫자를 붙이지 않고
"알수없음"이라고만 적는다 — 숫자를 붙이면 마치 "관여하지 않았음을 측정해서 확인했다"는
뜻으로 보이기 쉽기 때문이다. 즉 `관찰 안 됨`은 사실상 앞서 말한 `unknown`(확인 불가)에
가깝다 — "아니다"가 아니라 "모른다"다.

## 트리거 매핑 표를 읽는 법

트리거 매핑 표는 3개 열로 구성된다: `근거 문구 | 트리거 | 등급 (참고용 수치)`.

- **근거 문구**: 프롬프트 원문 중 판정의 근거가 된 부분(가독성을 위해 짧게 축약됨).
- **트리거**: 발동 여부를 판정하는 대상. 이름 앞에 종류를 괄호로 붙여 한눈에 구분한다 —
  `(Skill: dataviz)`, `(Rule: CLAUDE.md)`, `(Tool: Bash)`처럼 Skill/지침(Rule)/Claude
  Code가 호출한 Tool(내장 Tool 또는 MCP tool) 중 하나로 표시된다. 별도의 "종류" 열은
  두지 않는다.
- **등급 (참고용 수치)**: 위에서 설명한 확인됨/강한 추정/약한 추정/
  관찰 안 됨 등급과 참고용 %(또는 관찰 안 됨의 "알수없음").

표가 가장 중요한 결과이기 때문에 옆으로 길게 늘어지지 않도록 근거 문구는 짧게 자르고,
**셀 안에서는 절대 줄을 바꾸지 않는다** — 한 근거 문구가 여러 트리거에 걸치면 한 셀에
몰아넣지 말고 행을 트리거 개수만큼 나눠 한 행에 트리거 하나씩만 적는다. raw newline은
물론 `<br>` 같은 HTML 태그도 쓰지 않는다 — 이 환경의 렌더러에 따라 줄바꿈이 아니라
글자 그대로("&lt;br&gt;") 노출되어 오히려 가독성을 해칠 수 있기 때문이다.

## % 표기에 대해

확인됨/강한 추정/약한 추정 표에 나오는 % 숫자(예: "72%")는 Claude
내부의 실제 판단 확률이 아니다. mason-report는 그런 값에 접근할 수 없다 — Hook에는
애초에 그런 값이 존재하지 않는다. 위 등급을 사람이 읽기 쉽게 시각화한 **참고용
수치**일 뿐이며("근사"라는 표현은 오히려 "실측에 가까운 계산값"처럼 오해되기 쉬워 쓰지
않는다), 구간 안에서의 구체적 숫자는 계산된 값이 아니라 표현적 장치다. 그래서 리포트에는
항상 등급 이름과 % 참고용 수치를 함께 적는다(예: "강한 추정 (~70%, 참고용)") —
% 단독 표기는 하지 않는다. 다만 관찰 안 됨에는 애초에 %를 붙이지 않고 "알수없음"만
적는다.

어긋나 보이면 그쪽이 최신 기준이다.
```
