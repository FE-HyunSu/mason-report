# Limitations

mason-report는 관찰 가능한 실행 증거만으로 동작한다. 아래 한계는 설계상 피할 수 없거나,
현재 MVP 범위에서 의도적으로 해결하지 않은 것들이다.

## 근본적 한계 (설계상 불가능)

- **chain-of-thought 접근 불가**: Claude의 비공개 내부 추론 과정은 Hook이나 transcript
  어디에도 노출되지 않는다. 이 플러그인은 그것을 추출하려 시도하지 않는다.
- **모델 내부 후보 비교 과정 접근 불가**: 왜 특정 Tool이나 접근법이 다른 대안 대신
  선택됐는지, 내부적으로 어떤 후보들이 고려됐는지는 알 수 없다.
- **로그에 없는 판단은 확인 불가**: 관찰된 행동으로부터 재구성한 "왜"는 항상 `inferred`
  등급이며, 실제 근거였는지는 검증할 수 없다.
- **파일을 읽었다고 지침을 실제로 따랐다고 확정할 수 없음**: `InstructionsLoaded`는
  파일이 컨텍스트에 로드됐다는 사실만 알려준다. 그 내용의 어떤 규칙이 실제로 이후
  행동에 영향을 미쳤는지는 로그만으로 알 수 없다(내용 자체를 저장하지 않기 때문에 더욱
  그렇다).
- **Skill 파일 접근과 Skill 활성화가 항상 동일하지 않음**: 파일이 컨텍스트에 노출된
  것과, 그 Skill의 절차가 실제로 적용된 것은 다르다. `decision-analysis` Skill은 이
  구분을 위해 4단계 증거 등급(확인됨/강한 추정/약한 추정/관찰 안 됨)을
  사용하지만, 이 자체도 로그가 명시적 신호(예: 전용 "Skill invoked" 이벤트)를 제공하지
  않는 한 완전히 확실할 수 없다.
- **Observer의 분석도 모델의 해석이므로 오류 가능**: `/mason-report:latest` 등이
  생성하는 리포트 자체도 Claude가 로그를 읽고 작성한 것이다. 로그가 정확해도, 그 로그를
  해석하는 과정에서 오류나 과잉 해석이 있을 수 있다.

## 버전/구현 의존적 한계

- **Hook 및 transcript 스키마의 버전 차이**: 이 문서와 코드는 공식 문서(`code.claude.com/docs/en/`)를
  기준으로 작성됐다. 일부 필드(특히 `PostToolUseFailure`의 오류 필드명)는 문서에서 원문
  그대로 재확인하지 못해 방어적으로 여러 후보 키를 시도하도록 구현했다 — 실제 필드명이
  다르면 해당 값이 비어 있을 수 있다. `UserPromptSubmit`의 프롬프트 텍스트 필드명(`prompt`)은
  2026-09-06에 실제 v2.1.178(VS Code 확장) 설치본으로 mason-report를 설치해 검증한
  결과, 정상적으로 채워지는 것을 확인했다. 정확한 지원 버전은 README의 "지원 Claude Code
  버전" 절을 참고한다.
- **`prompt_id`의 최소 지원 버전은 문서와 실측이 불일치함**: 공식 문서는 "v2.1.196 이상
  필요"라고 적고 있으나, 2026-09-06에 v2.1.178(VS Code 확장, Agent SDK 백엔드)에서 실제로
  `promptId`가 정상 채워지는 것을 직접 확인했다. 따라서 이 최소 버전 요구사항은 신뢰할 수
  없는 것으로 정정한다 — 정확한 조건(버전별인지, 클라이언트 표면별인지)은 확인되지
  않았다(unknown). `promptId`가 비어 있는 경우를 대비한 시간 구간 기반 추정(`inferred`)
  폴백은 계속 유지한다.
- **transcript 비동기 기록**: `transcript_path`가 가리키는 파일은 비동기로 기록되어
  현재 턴의 최신 메시지를 아직 반영하지 않을 수 있다. 이 플러그인은 이 문제를 피하기
  위해 `Stop`/`SubagentStop`의 `last_assistant_message` 필드에 의존하며, "방금 끝난
  턴"의 transcript는 직접 파싱하지 않는다. 다만 토큰 사용량 계산(`computeTokenUsageForTurn`,
  `docs/event-schema.md` 참고)은 예외다 — `Stop` 이벤트가 이미 관찰된, 즉 시간이 지난
  **완료된 과거 턴**에 한해서만 transcript를 읽으므로 이 비동기 위험이 적용되지 않는다.
  아직 `Stop`이 관찰되지 않은 턴에 대해서는 토큰 사용량을 계산하지 않고 "확인 불가"로
  남긴다.
- **토큰 사용량은 이 기능 도입 이후 기록된 로그에만 존재함**: `transcriptPath` 필드는
  이 기능 추가 이전에 캡처된 이벤트에는 없다. 그런 옛 로그를 대상으로 한 턴은
  `transcript_path_not_captured` 사유로 토큰 사용량이 "확인 불가"로 표시된다 — 계산이
  실패했다는 뜻이 아니라, 애초에 계산에 필요한 정보가 로그에 없다는 뜻이다.
- **Subagent 토큰 포함 여부는 항상 명시적으로 분리**: 같은 턴 안에서 Task tool로 실행된
  Subagent가 있으면, 그 Subagent가 소비한 토큰은 transcript에서 `isSidechain: true`로
  구분된다. mason-report는 이를 메인 대화 토큰과 합산하지 않고 항상 별도 항목으로
  보고한다 — "이 턴이 쓴 토큰"의 정의(메인만? Subagent 포함?)는 사용자가 리포트를 읽을
  때 직접 판단해야 하는 부분이기 때문이다.
- **로컬 실행 환경 미검증**: 이 리포지토리를 만든 환경에는 실제로 동작하는 Claude Code
  CLI 바이너리가 설치되어 있지 않았다(npm wrapper 패키지만 존재, 네이티브 바이너리는
  placeholder 상태). 따라서 실제 Claude Code 세션에서 Hook이 이 스크립트를 정확히 이
  문서대로 호출하는지는 **문서 기반으로 구현했을 뿐, 실제 Claude Code 프로세스를 통한
  end-to-end 실행으로 검증하지 못했다.** 사용자는 설치 후 `/mason-report:status`로 실제
  동작 여부를 직접 확인해야 한다.

## 정책상 의도적으로 다루지 않는 것

- 파일 내용, diff, 원본 Tool 결과 전체 — 개인정보/보안 원칙에 따라 저장하지 않으므로,
  "정확히 무엇이 바뀌었는지"는 이 로그만으로 재구성할 수 없다.
- 마스킹은 알려진 패턴 기반이라 완전하지 않다(자세한 내용은
  [privacy.md](./privacy.md) 참고).
- 여러 Claude Code 세션이 같은 프로젝트에서 동시에 실행되는 경우의 완전한 동시성
  보장(파일 append는 대체로 안전하지만, 모든 OS/파일 시스템 조합에서 검증되지는
  않았다).
